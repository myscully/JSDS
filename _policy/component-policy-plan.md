## 0. 읽는 법

컴포넌트마다 네 칸으로 적었습니다.

- **지금** — 코드에서 확인한 현재 동작. 확인하지 못한 것은 적지 않았습니다.
- **고칠 것** — 현재 문서 · 코드가 틀렸거나, 보안 콘솔에서 사고로 이어질 수 있는 것.
- **더할 정책** — 지금 비어 있어 정해 두면 좋은 규칙.
- **결정** — 사람이 정해야 하는 것. 해당 컴포넌트를 시작할 때 선택지로 묻습니다.

출처 표시는 `[A]` 외부 시스템 · `[K]` 외부 시스템 · `[T]` 외부 서비스 · `[W]` 기준 시스템 입니다. 표시가 없으면 우리 코드나 보안 콘솔 맥락에서 나온 제안입니다. `(검사)` 는 `verify` · `behave` 로 강제할 수 있다는 뜻입니다.

**근거의 한계**

- 외부 시스템 은 usage 29쪽 중 28쪽을 읽었습니다. Navigation system 은 404 였고, Button · Form · Lozenge · Tabs 의 뒷부분은 원문이 아니라 요약으로 읽었습니다.
- 첨부한 세 문서에는 공식 문서와 핸드오프 번들 관찰값이 섞여 있고, 문서 스스로 그렇게 밝힙니다. 그래서 **픽셀값은 가져오지 않고 사용 규칙만** 참고했습니다.
- 동작은 소스를 읽어 확인했습니다. 브라우저에서 잰 것은 없습니다. placeholder 대비 1.33 은 토큰 값을 합성해 계산한 수치입니다. 각 컴포넌트를 고칠 때 헤드리스로 다시 잽니다.

**걸러 낸 기준.** 우리 시스템은 1024px 이상 데스크톱 콘솔만 지원하고(1023 이하 미지원), 밀도가 높으며, 운영자가 매일 씁니다. 모바일 소비자 앱인 외부 서비스 · 외부 서비스의 규칙과 대국민 서비스인 외부 시스템 의 규칙은 이 조건에 맞을 때만 옮겼습니다. 뺀 것은 6절에 이유와 함께 적었습니다.

## 2. 공통 정책 — 컴포넌트보다 먼저 정할 것

아래는 여러 컴포넌트에 걸쳐 있어 하나씩 정하면 어긋납니다. Foundations 또는 패턴에 한 번 쓰고 컴포넌트는 참조합니다.

### P1. 비활성(Disabled)

- **지금** Button 은 비활성 표현만 있고 언제 쓰는지는 없습니다. Card 는 이유 줄을 보이게 합니다. Date Picker '적용' 은 값이 바뀌어야 켜집니다.
- **결정(첫 항목) · 제안(나머지)**
  - 폼 제출 버튼은 비활성으로 두지 않고, 누르면 검증하고 오류로 안내합니다. [A] 비활성 버튼은 포커스가 가지 않아 이유를 알 수 없습니다.
  - 권한 · 상태 때문에 할 수 없는 동작은 비활성으로 두고 이유를 화면에 적습니다. 권한이 아예 없는 메뉴는 숨깁니다.
  - 비활성 요소에 Tooltip 을 달지 않습니다. [A]
  - 예외: 오버레이 안 '적용' 처럼 바뀐 것이 없어서 누를 일이 없는 버튼.
- 외부 서비스는 금액이 0 이면 CTA 를 잠급니다. 입력 하나짜리 모바일 흐름의 규칙이라 긴 정책 폼에는 맞지 않습니다.

### P2. 입력 오류

- **지금** 입력 폼 패턴에 포커스가 떠날 때 필드 단위 검증, 제출 시 첫 오류로 스크롤, 오류 3개 이상이면 상단 요약이 있습니다. Select · Checkbox · Radio 에는 오류 상태 자체가 없습니다.
- **제안**
  - 패턴의 규칙을 모든 입력 컴포넌트의 공통 규칙으로 올립니다.
  - Select · Checkbox 그룹 · Radio 그룹에 오류 상태를 더합니다. (검사)
  - 고치면 오류를 바로 지웁니다. [A]
  - 오류 문구 영역은 `aria-live="polite"` 입니다. [A]
  - 입력값은 오류가 나도 지우지 않습니다. [A]
  - 자주 나는 오류 문구는 사전으로 모읍니다. [T] 외부 서비스의 오류 메시지 라이브러리처럼, 좋은 문구를 기본값으로 만드는 장치입니다. Date Picker `messages` 가 첫 사례입니다.

### P3. 오버레이 공통

| 규칙 | 내용 |
| --- | --- |
| 하나만 | 모달 위에 모달을 띄우지 않습니다. [A] |
| Esc | 가장 안쪽 것 하나만 닫습니다. Popup 안의 Select 가 열려 있으면 Select 만 닫습니다. |
| 배경 클릭 | 입력 중이거나 위험 확인이면 닫지 않습니다. |
| 포커스 | 열면 안으로 옮기고, 닫으면 연 요소로 돌아갑니다. Popup 은 이미 그렇습니다. |
| 쌓임 | Toast 는 모달 위에 보입니다. [A] 지금 Toast 110 · 배경 100 으로 맞습니다. |
| 잘림 | `overflow` 안의 작은 오버레이가 잘리지 않아야 합니다. Tooltip 이 지금 문제입니다. |

### P5. 위험 동작의 단계

UX 원칙 3 "되돌릴 수 있게" 를 규칙으로 구체화합니다.

| 영향 | 흐름 |
| --- | --- |
| 되돌릴 수 있음 | 바로 실행 → Toast + 실행 취소 |
| 되돌리기 어려움 | Popup 확인 → 실행 → 결과 알림 |
| 복구 불가 + 대량 | Popup + 대상 수 표시 + 확인 문구 입력 → 실행 → 결과 알림 |

위험 확인의 첫 포커스는 취소 쪽에 둡니다. 보안 기능을 끄는 Switch 도 이 표를 따릅니다.

### P6. 넘침과 말줄임

- 말줄임은 마지막 수단입니다. [A]
- 줄인 글자는 키보드로도 전체를 볼 수 있어야 합니다. `title` 속성은 키보드로 볼 수 없습니다. Breadcrumb 와 접힌 SideNav 가 지금 `title` 을 씁니다.
- 포커스를 받을 수 없는 요소(Tag 등)는 말줄임하지 않도록 길이를 제한합니다. [A]

### P7. 문구

- Writing 페이지에 종결 규칙이 없습니다. **합니다체를 명시**합니다. 기존 문구와 맞고, 업무 도구의 톤으로 맞습니다. [K]
- 해요체는 가져오지 않습니다. [T][W] 소비자 앱의 톤입니다.
- 질문형은 확인 대화상자와 빈 화면 제목에만 씁니다. 이 부분은 이미 있습니다.
- 라벨 · 목록 항목에 마침표를 찍지 않습니다. [A][W]

> **정비 완료(2026-11-09, 사람의 결정 넷).** placeholder 는 tertiary(라이트 3.67 · 다크 3.66 — 4.5 미달이라 이유를 적은 예외). 입력 검증은 시스템이 제공(사이트 `form[data-validate]` · React `Form validate`). 필드 버튼은 비밀번호 표시만 더함. 글자 수 한도는 넘겨도 입력되고 오류로 안내. 규칙은 페이지 원칙 표에 있습니다. 아래는 정비 전에 적은 원문입니다.

- **지금** sm · md · lg, prefix · suffix, 카운터, Textarea, disabled · readonly, `aria-invalid` · `aria-describedby` 연결. Date Picker 의 기반입니다.
- **고칠 것**
  - placeholder 색이 비활성 토큰(`--foreground-disable-primary`, 16%)입니다. 흰 바탕 합성 대비 **1.33** 으로 거의 보이지 않습니다. `contrast.pairs.js` 의 면제 사유 "비활성 컨트롤" 은 placeholder 에 해당하지 않습니다. Search · Select 도 같습니다.
- **더할 정책**
  - placeholder 를 라벨 대신 쓰지 않습니다. 예시 · 형식은 입력 후에도 보이게 도움말에 씁니다. [A] (검사: 라벨 없는 입력)
  - 필수가 있는 폼은 상단에 `* 필수` 범례를 둡니다. [A]
  - 입력 종류별 규칙: 비밀번호 표시 토글, 숫자, IP · URL · 해시는 고정폭, 지우기 버튼 사용 조건. 지금은 종류별 규칙이 없습니다.

## 5. 추가 제안 컴포넌트

> **v1.0 범위(사람의 결정 2026-11-10).** 넣는 것: Form · Empty State · Page Header · File Upload · Avatar · Link · Code · Copy Field · Number Input · Time 입력. 넣지 않는 것: Inline Edit · Tree · 알림 센터(v1.0 완료 뒤 다시 묻습니다). 승격 묶음(Form · Empty State · Page Header · Avatar · Link)을 먼저, 새로 만드는 묶음(File Upload · Code · Copy Field · Number Input · Time 입력)을 다음에 진행합니다.

> **새로 만드는 묶음의 결정(사람의 결정 2026-11-10).** 다섯 전부 v1.0 에 넣습니다.
> - **File Upload** — 드롭 · 파일 선택 · 형식과 용량 오류 · 진행 표시 · 재시도 버튼까지 시스템이 맡습니다. 실제 전송은 제품이 하고 진행률과 실패만 알려 줍니다.
> - **Copy Field** — 민감한 값은 기본으로 가리고 보기 버튼으로 펼칩니다. 복사는 가린 채로도 전체 값을 복사합니다.
> - **Code** — 구문 강조 없이 고정폭 글자 · 복사 버튼 · 줄바꿈 또는 가로 스크롤만 둡니다.
> - **Number Input** — 입력칸 안에 증감 버튼과 단위를 둡니다. 위 · 아래 화살표 키로도 바꿉니다. 범위를 벗어난 값은 입력을 받고 오류로 알립니다.
> - **Time 입력** — 별도 컴포넌트 대신 Date Picker 의 시각 옵션입니다. 값 하나(`YYYY. MM. DD HH:mm`, 24시간제)로 다루고 시간대 · 순서 검증을 그대로 씁니다. 초(`HH:mm:ss`)는 옵션입니다.

## 7. 진행 순서

### 순서

0. **공통 정책**: 2절의 P1~P9 와 페이지 구성(1절)
1. **입력**: Text Field → Search → Select → Dropdown. Date Picker 의 기반을 바로 잇습니다.
2. **선택**: Checkbox · Radio · Switch · Select Button · Chip · Slider
3. **피드백 · 오버레이**: Notification · Popup · Tooltip · Loading + Side Panel
4. **데이터**: Data Table · Pagination · Table · List · Item Tile
5. **탐색 · 표시**: Tab · Navigation · Top Navigation · Tag · Indicator · Divider

관련 컴포넌트를 묶는 이유는 경계를 함께 정해야 하기 때문입니다. Radio 와 Select 사이의 어긋남처럼, 따로 고치면 서로 다른 말을 하게 됩니다.

### 일정

WBS 는 Components 완료 11.06, v1.0 공개 11.30 입니다. 오늘이 11.09 이므로 이미 지났습니다.

- 10.28 ~ 11.09 의 13일 동안 전면 정의한 컴포넌트는 6개입니다(Button · Accordion · Breadcrumb · Card · Data Visual · Date Picker).
- 같은 속도면 남은 25개에 약 54일이 걸립니다. 11.30 까지는 21일입니다.
- 패턴 11개 · QA · Figma 일괄 반영도 그 안에 들어 있습니다. 따라서 **25개 모두를 Date Picker 깊이로 하면서 11.30 을 지킬 수는 없습니다.**
