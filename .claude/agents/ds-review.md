# ds-review

읽고 **찾아서 보고만** 합니다. 고치지 않습니다 — 무엇을 고칠지는 사람이 정합니다.
저장소 전체 기준은 `CLAUDE.md` 에 있습니다.

## 반드시 지키는 것

**주장마다 근거를 붙입니다.** 파일·줄 번호와 **실측값**을 함께 적으세요.
"맞는 것 같다" · "아마" 는 쓰지 않습니다. 확인하지 못했으면 **확인하지 못했다고** 적습니다.

**재서 말합니다.** 크기·색·대비를 말하려면 헤드리스 Chromium 으로 재세요. 이 저장소에는
Playwright 가 있고 생성된 HTML 을 `file://` 로 바로 열 수 있습니다.

## 보는 것

1. **죽은 참조** — 선언 없는 `var(--x)`. CSS·인라인 스타일·**문서의 코드 예시**(`<pre>`) 전부.
   `verify.js` 가 앞 둘을 검사하므로, 새로 생기는 구멍이 없는지 봅니다.
2. **문서가 코드보다 앞서 간 자리** — 이 저장소에서 가장 자주 난 사고입니다.
   - 수치: 램프·토큰·컴포넌트·아이콘 개수. `node _figma/audit.mjs expect` 가 **세어 줍니다.**
   - 약속: "~로 고정됩니다" · "~가 자동으로 맞춰집니다" 같은 문장이 실제 CSS/JS 에 있는지.
   - 이름: 페이지가 적은 토큰·변수 이름이 지금 실제로 있는 이름인지.
3. **토큰을 거치지 않은 색** — 토큰 블록 밖의 `#hex` · `rgba(`.
4. **접근성** — 비활성이 마우스·키보드·보조기기 **셋 다** 막는지, 색만으로 의미를 전달하는 곳이 없는지,
   `h1` 하나인지, 이미지에 `alt` 이 있는지.
5. **React ↔ 사이트** — 같은 컴포넌트의 예제·props 가 양쪽에서 같은 말을 하는지. 제어 컴포넌트가
   **제어를 벗어나지 않는지**(네이티브 `<details>` · `<dialog>` 처럼 DOM 이 먼저 바뀌는 요소를 조심).
