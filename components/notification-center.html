Notification CenterN

상단 바의 벨 버튼으로 여는 지난 알림 목록입니다. Toast 로 지나간 탐지 · 배포 · 계정 알림을 다시 보고, 안 읽은 것을 골라 관련 화면으로 갑니다.

언제 쓰는가
실시간 탐지처럼 흘려보내면 놓칠 수 있는 알림을 쌓아 두고 나중에 다시 보게 할 때 씁니다. 안 읽은 수를 벨에 보여 주고, 항목을 누르면 그 알림의 관련 화면으로 갑니다.
비슷한 것
방금 한 동작의 결과는 Toast, 화면 일부의 지속 상태는 Notice, 제품 전체에 영향을 주는 상태는 Banner 입니다. 알림을 검색하고 오래 쌓아 보는 이력 화면은 Data Table 로 따로 만듭니다.
Placement
Top Navigation 오른쪽 — 검색 다음, 사용자 메뉴 앞

Default

벨을 누르면 열립니다. 안 읽은 항목은 점과 굵은 제목으로 보이고, 누르면 읽음이 되며 관련 화면으로 갑니다. 이 예제는 열린 채로 시작합니다.

Rules

열기
벨 버튼 아래에 비모달 대화상자로 엽니다. 열면 포커스가 패널로 가고, Esc 를 누르면 닫히며 벨로 돌아옵니다. 바깥을 누르거나 Tab 으로 패널을 떠나도 닫힙니다.
읽음
항목을 누르면 그 항목만 읽음이 됩니다. 열기만 해서는 바뀌지 않습니다. 머리의 '모두 읽음' 은 안 읽은 것을 한꺼번에 읽음으로 바꾸고, 남은 것이 없으면 꺼집니다. 서버에 저장하는 일은 제품이 ds:notify-read 를 받아 합니다.
항목
누르면 관련 화면으로 갑니다. 그래서 항목은 링크이고, 갈 화면이 없는 알림은 버튼이라 누르면 읽음만 됩니다. 항목 안에 다른 버튼을 두지 않고, 알림 하나를 지우는 동작도 두지 않습니다.
안 읽은 수
벨의 Count · 접근 이름 · Tooltip · '안 읽음' 탭의 수를 시스템이 함께 맞춥니다. 99 를 넘으면 99+ 이고, 0 이면 배지를 숨깁니다.
새 알림
제품이 DS.notify.add(React 는 items)로 넘기면 맨 위 '오늘' 묶음에 넣고 수를 늘리며 화면 낭독기에 알립니다. 알림을 받아 오는 연결은 제품의 몫입니다.
목록
'전체' 와 '안 읽음' 탭으로 거르고, 목록 안은 오늘 · 어제 · 이전 같은 날짜 묶음으로 나눕니다. 묶음 이름과 '10분 전' 같은 시각 글자는 제품이 정합니다. 심각도가 있는 알림만 앞에 심각도 Tag 를 둡니다.
이전 알림
목록 끝의 '이전 알림 보기' 가 ds:notify-more 를 냅니다. 불러오는 동안 버튼에 스피너가 돌고, 실패하면 버튼 위에 알리고 '다시 시도' 로 바뀝니다. 끝이면 resolve(items, {done:true}) 로 버튼을 없앱니다.
