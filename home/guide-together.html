요구 정리

누가 무엇을 보고 무엇을 하는 화면인지 한 문장으로 정합니다. 이 예시에서는 보안 관리자가 오늘 들어온 로그를 심각도와 기간으로 거르고, 한 건을 펼쳐 원본을 봅니다.

왜한 문장이 있어야 다음 단계에서 고를 틀과 부품이 좁혀집니다.

해보기지금 만들 화면을 같은 형식으로 한 문장으로 적어 보세요.

패턴과 템플릿 고르기

로그를 거르고 펼쳐 보는 일은 로그 뷰어 패턴이 풀고, 목록 화면의 틀은 리스트 템플릿이 줍니다. 둘을 고르면 화면의 뼈대가 정해집니다.

왜기획자와 디자이너가 같은 틀을 보고 시작하면 화면 구성을 두고 다시 맞출 일이 없습니다.

이름 맞추기

화면에 들어갈 부품의 이름을 셋이 같은 목록으로 정합니다. 이 예시에서는 Search · 필터 Chip · Date Picker 기간 · Data Table 행 펼침 · 심각도 Tag 입니다.

왜같은 목록을 보면 기획서 · Figma · 코드가 한 이름으로 이어집니다.

상태와 문구

결과가 없을 때 · 불러오는 중 · 조회에 실패했을 때 · 권한이 없을 때의 화면과 문구를 정합니다. 버튼 이름과 오류 문구는 Writing 규칙으로 씁니다.

왜이 단계에서 상태가 정해져야 디자이너가 상태 화면을 함께 그리고, 개발자가 같은 문구를 씁니다.

Figma 로 그리기

리스트 템플릿의 구성대로 인스턴스를 놓고, 앞에서 정한 이름의 컴포넌트와 속성으로 그립니다. 정상 화면과 상태 화면 넷을 함께 그립니다.

왜정한 이름 그대로 그리면 개발자가 Figma 를 열고 바로 같은 컴포넌트를 찾습니다.

코드로 옮기기

리스트 템플릿의 코드에서 시작해 로그 뷰어 예제의 코드를 가져와 붙입니다. 거르기와 펼치기 동작은 시스템이 하고, 제품은 이벤트를 받아 조회만 연결합니다. 마치면 셋이 공통 트랙의 넘기기 전 확인으로 함께 점검합니다.

왜같은 템플릿과 예제에서 출발하면 디자인과 코드가 처음부터 같은 모양입니다.
