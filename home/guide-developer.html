설치하기

React 제품은 패키지를 설치하고 스타일 파일을 한 번 불러옵니다. 그 밖의 제품은 저장소의 스타일 파일 · 동작 스크립트 · 서체 폴더를 함께 넣고 페이지에 연결합니다.

왜한 번 연결하면 모든 컴포넌트의 모양과 기본 동작이 따라옵니다.

npm i @jiran/ds-react

// main.tsx — 앱 진입점에서 한 번
import "@jiran/ds-react/style.css";   // 토큰 + 컴포넌트 CSS (사이트 크롬 제외)
import { ToastProvider, applyProductColor } from "@jiran/ds-react";

applyProductColor("red");            // 제품 색 팔레트 키(blue · red · cyan · navy · orange · neutral · ai) → --prod-40~60 · data-accent

createRoot(document.getElementById("root")!).render(
  <ToastProvider>
    <App />
  </ToastProvider>,
);
<!-- assets/ 폴더(style.css · ds.js · fonts/)를 프로젝트에 복사한 뒤 -->
<link rel="stylesheet" href="assets/style.css">
<script src="assets/ds.js" defer></script>
해보기새 프로젝트에 설치하고 버튼 하나를 그려 서체가 Pretendard 로 보이는지 확인해 보세요.

제품 색 · 테마 · 루트

앱을 시작할 때 제품 색 팔레트의 키 하나를 정하고, 다크 테마는 문서의 가장 바깥 요소에 정합니다. 앱 루트에는 시스템의 루트 클래스를 붙입니다.

왜루트 클래스가 없으면 서체와 본문 색이 브라우저 기본으로 돌아갑니다. 제품 색은 키 하나로 버튼 · 링크 · 선택 표시가 모두 바뀝니다.

<!-- 다크 테마: html 요소에 지정. 없으면 시스템 설정을 따릅니다 -->
<html data-theme="dark">
<!-- 앱 루트에 .ds-root 를 붙이면 서체·본문 색·배경 토큰이 적용됩니다 -->
<div id="root" class="ds-root"></div>
/* 1) html 요소에 data-accent="키" — red · cyan · navy · orange · neutral · ai. 파랑(기본)은 적지 않습니다.
      빨강 · 주황의 중립 입력 링, AI 의 그라데이션 면, 중립 제품의 회색 단계가 이 속성으로 걸립니다 */
/* 2) 빨강 · 시안 · 남색 · 주황 · AI 는 다섯 단계를 :root 에 넣습니다. 아래는 빨강(#C30D2A)의 값입니다 */
:root{
  --prod-40:#980A21; --prod-45:#B00C26; --prod-50:#C30D2A; --prod-55:#DB0F2F; --prod-60:#F34B65;
}
/* 남색처럼 어두운 제품 색은 다크 주 면용 --prod-50d 도 넣습니다. Design Token › Product color 적용의 함수가 계산해 줍니다 */
/* 중립은 다섯 단계를 넣지 않습니다. 넣지 않으면 기본 파랑이 쓰입니다 */
해보기제품 색 키를 바꿔 가며 주 버튼 색이 사이트 헤더의 제품 색 메뉴와 같게 바뀌는지 확인해 보세요.

예제 코드 가져오기

컴포넌트 페이지의 예제 아래 코드 보기에서 HTML+CSS 나 React 코드를 복사합니다. React 의 속성 이름은 HTML 의 클래스 이름과 같아서, 사이트 예제와 제품 코드를 그대로 맞대 볼 수 있습니다.

왜예제 코드는 사이트에서 실제로 돌아가는 코드이고, React 예제는 사이트 예제와 구조가 같은지 테스트로 확인합니다.

import { Button, TextField, Tag } from "@jiran/ds-react";

<TextField label="정책 이름" required />
<Tag tone="critical">Critical</Tag>
<Button size="md" variant="solid" color="primary">정책 저장</Button>
<!-- 컴포넌트 페이지 HTML+CSS 탭에서 복사한 마크업을 그대로 붙입니다 -->
<button class="btn md solid primary">정책 저장</button>
<span class="tag critical">Critical</span>

<script>
  DS.init(document.getElementById("dynamic-area")); // 나중에 DOM 에 넣은 마크업만 한 번
</script>
해보기Button 페이지의 Size 예제를 복사해 내 화면에 붙이고 세 크기가 사이트와 같은지 비교해 보세요.

동작과 이벤트

드롭다운 · 탭 · 달력 · 폼 검증 같은 동작은 시스템이 붙입니다. 제품은 값이 바뀌었다는 이벤트나 콜백을 받아 저장과 조회만 합니다. HTML 제품은 나중에 화면에 넣은 마크업만 한 번 초기화합니다.

왜동작을 직접 다시 짜면 키보드 · 포커스 · 화면 낭독 규칙이 어긋납니다.

import { Form, TextField, Button } from "@jiran/ds-react";

// 검증 · 포커스 · 오류 문구는 Form 이 맡고, 제품은 통과한 값만 저장합니다
<Form validate onSubmit={(e) => { e.preventDefault(); save(new FormData(e.currentTarget)); }}>
  <TextField label="정책 이름" name="name" required />
  <Button type="submit" variant="solid" color="primary">저장</Button>
</Form>
<!-- 동작은 ds.js 가 붙이고, 제품은 문서에서 이벤트를 듣습니다 -->
<form class="form" data-validate> … </form>

<script>
  document.addEventListener("ds:select", (e) => load(e.detail.value)); // Select Button 값이 바뀜
  document.addEventListener("ds:tab", (e) => remember(e.detail.index)); // 탭을 옮김
  DS.init(document.getElementById("dynamic-area"));                    // 나중에 넣은 마크업만 한 번
</script>
해보기Form 페이지의 예제에서 빈 칸으로 제출해 첫 오류로 포커스가 가는지 보고, 같은 폼을 내 화면에 붙여 똑같이 동작하는지 확인해 보세요.

템플릿 코드에서 시작

Templates 의 각 화면 페이지에서 코드 보기를 열면 화면 전체 HTML 과 앱 틀 배치 CSS 를 가져올 수 있습니다. 상단 바 · 사이드 내비 · 머리글 · 본문의 배치를 그대로 두고 내용만 바꿉니다.

왜틀을 처음부터 짜지 않으면 좁은 화면의 내비 접힘이나 여백 같은 약속을 그대로 지킬 수 있습니다.

넘기기 전 점검

색과 간격은 시스템의 이름만 썼는지, 입력칸과 아이콘 버튼마다 접근 이름이 있는지, 화면의 문구가 Writing 규칙대로인지 봅니다. 지원 환경은 너비 1024 이상의 데스크톱과 키보드 조작입니다.

왜이름 없는 색은 다크 테마와 제품 색을 따라가지 않고, 이름 없는 아이콘 버튼은 화면 낭독기에서 무엇인지 알 수 없습니다.

해보기마우스를 쓰지 않고 키보드의 Tab 과 Enter 만으로 내 화면의 주요 동작을 끝까지 해 보세요.
