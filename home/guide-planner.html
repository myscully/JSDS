기획자N

기획서를 이 시스템의 말로 쓰는 여섯 단계입니다. 화면을 처음부터 그리지 않고 있는 틀과 부품에서 고르고, 정상 화면 밖의 상태와 문구까지 정합니다.

1 / 6 단계

화면 종류 고르기

만들 화면이 Templates 의 어느 화면에 가까운지 먼저 봅니다. 목록 · 설정 · 대시보드처럼 틀이 정해지면 Patterns 에서 그 안에 들어갈 업무 단위를 고릅니다. 검색 · 로그 뷰어 · 위험 작업 확인이 그런 단위입니다.

왜처음부터 그리지 않고 고르면 다른 제품과 같은 흐름이 되고, 디자인과 개발도 이미 있는 것에서 시작합니다.

해보기Templates 개요에서 만들 화면과 가장 비슷한 것을 고르고, 그 페이지의 Composition 에 적힌 패턴을 확인해 보세요.

2 / 6 단계

컴포넌트 정하기

기획서의 입력 · 선택 · 알림마다 컴포넌트 페이지의 고르기 표에서 언제 쓰는가를 읽고 정합니다. 하나만 고르면 Select, 검색해서 여러 개 고르면 Combobox 처럼 고르는 기준이 적혀 있습니다.

왜부품이 정해지면 동작 · 키보드 · 오류 표시가 시스템이 정해 둔 대로 따라옵니다. 기획서에 동작을 따로 길게 적지 않아도 됩니다.

해보기기획 중인 화면의 선택 칸 하나를 골라 Select · Combobox · Radio Button 중 무엇이 맞는지 고르기 표로 정해 보세요.
관련 문서
  • Select
  • Combobox

3 / 6 단계

상태 정하기

정상 화면과 함께 네 가지 상태를 적습니다. 데이터가 없을 때, 불러오는 중, 실패했을 때, 권한이 없을 때입니다. 각 상태에는 Empty State · Loading 컴포넌트와 오류 · 권한 없음 패턴이 있습니다.

왜상태가 빠진 기획서는 디자인과 개발 중에 같은 질문을 다시 받게 됩니다.

해보기오류 · 권한 없음 패턴을 보고, 내 화면에서 권한이 없을 때 보일 문구를 한 줄 써 보세요.
관련 문서
  • Empty State
  • Loading
  • 오류 · 권한 없음
4 / 6 단계

문구 쓰기

문장은 합니다체로 쓰고, 버튼은 누르면 일어나는 일을 이름으로 붙입니다. 오류 문구는 무엇이 일어났는지와 고치는 법을 함께 적습니다. 자세한 규칙은 Writing 페이지에 있습니다.

왜문구 규칙이 같아야 제품이 달라도 한 회사의 제품으로 읽힙니다. '자세히' 나 '클릭' 처럼 모호한 이름은 누르기 전에 무엇이 열릴지 알려 주지 않습니다.

해보기기획서의 버튼 이름 다섯 개를 Writing 의 버튼 이름 규칙에 비춰 보고, 모호한 것을 바꿔 보세요.
관련 문서
  • Writing
5 / 6 단계

위험 동작과 알림 고르기

되돌릴 수 없는 일에는 위험 작업 확인을 붙이고, 결과를 알릴 때는 Toast · Banner · Notice 중 하나를 고릅니다. 무엇을 언제 쓰는지는 Interaction 페이지의 알림 고르기와 위험 동작 규칙에 있습니다.

왜같은 일에 같은 확인과 알림이 붙어야 사용자가 다음에 일어날 일을 예측합니다.

해보기기획 중인 화면의 삭제 버튼 하나에 확인 팝업이 필요한지 Interaction 의 규칙으로 판단해 보세요.

6 / 6 단계

기획서에 이름 쓰기

화면 설명에 컴포넌트 이름과 변형을 그대로 씁니다. 예를 들어 '목록은 Data Table, 행 선택과 고정 헤더' 처럼 적습니다. 이름이 모호하면 UI Dictionary 에서 생김새로 찾습니다.

왜디자이너와 개발자가 같은 이름으로 바로 찾을 수 있어 해석하는 시간이 줄어듭니다.

해보기기획서의 화면 하나를 골라 들어가는 컴포넌트 이름을 모두 적어 보세요.
