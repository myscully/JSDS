지도 보기

이 시스템은 네 층으로 쌓여 있습니다. Foundations 가 색 · 글자 · 간격 같은 기본값을 정하고, Components 가 그 값으로 버튼이나 표 같은 부품을 만듭니다. Patterns 는 부품을 엮어 오류 화면이나 로그 뷰어 같은 업무 단위를 풀고, Templates 는 그것을 모아 콘솔 화면 하나를 통째로 보여 줍니다.

왜어느 층에서 찾을지 알면 길을 잃지 않습니다. 화면 전체가 필요하면 위층인 Templates 부터, 부품 하나가 궁금하면 Components 부터 봅니다.

해보기상단 메뉴를 왼쪽부터 차례로 눌러 각 개요 페이지를 훑어보세요.

같은 이름 쓰기

같은 부품을 디자이너는 Figma 속성으로, 기획자는 화면 설명으로, 개발자는 코드로 부릅니다. 이 시스템은 세 이름을 하나로 맞춰 두었습니다. 컴포넌트 페이지의 Props 표에 적힌 이름이 Figma 의 속성 이름이자 코드의 이름입니다.

왜회의에서 '회색 작은 꼬리표' 대신 'Tag' 라고 말하면 서로 다시 묻는 일이 줄어듭니다. 이름이 떠오르지 않으면 UI Dictionary 에서 생김새로 찾습니다.

고르는 법

컴포넌트 페이지는 정의 바로 아래 고르기 표로 시작합니다. 언제 쓰는가 · 비슷한 것 · 놓는 자리를 먼저 읽고, 예제로 생김새와 상태를 본 뒤, Rules 에서 지켜야 할 규칙을 확인합니다.

왜겉모습이 닮은 부품이 많습니다. Select 와 Combobox, Chip 과 Tag 처럼 헷갈리는 짝은 고르기 표의 비슷한 것 행이 경계를 정해 줍니다.

색과 테마

제품마다 다른 것은 제품 색 하나뿐입니다. 팔레트 일곱 가지 중 하나를 고르면 주 버튼 · 링크 · 선택 표시가 함께 바뀌고, 무채색 · 상태색 · 간격은 모든 제품이 같습니다. 다크 테마에서도 같은 이름의 색이 알아서 바뀝니다.

왜색을 직접 고르지 않고 이름 있는 색만 쓰면 제품 색과 다크 테마가 따라옵니다. 직접 고른 색은 테마가 바뀌어도 그대로 남습니다.

해보기헤더의 제품 색 메뉴에서 색을 바꾸고 테마 버튼으로 다크로 바꿔, 이 페이지의 버튼과 단계 표시가 어떻게 달라지는지 보세요.

넘기기 전 확인

화면을 다음 사람에게 넘기기 전에 문구 · 상태 · 키보드 세 가지를 봅니다. 문구는 합니다체와 버튼 이름 규칙을 지켰는지, 상태는 빈 화면 · 불러오는 중 · 오류 · 비활성이 모두 정해졌는지, 키보드는 마우스 없이 끝까지 갈 수 있는지 봅니다.

왜기본 상태만 정한 화면은 개발 중에 빈 화면과 오류를 다시 묻게 됩니다. 세 가지를 미리 보면 되돌리는 일이 줄어듭니다.
